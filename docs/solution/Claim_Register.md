## How to use this register

| Status | Meaning | Allowed green |
|---|---|---|
| **proven** | Verified on real evidence + regression or documented run | L1 unit recall; L2 only if claim says so |
| **partial** | Some strategies work; not the full product claim | L0–L1; L2 only for proven sub-shapes |
| **specified-unbuilt** | Design/requirements named it; code incomplete or absent | Must not claim “works”; OOS or fail L2 |
| **unevidenced** | No solid sample yet | No product claim |
| **OOS** | Explicitly out of product scope for now | Silence OK only if scope-limitation id present |

**Rule:** Do not mark STATUS “built” for a cell here without evidence pointer + validation layer that is allowed to green.

## Process note — how Lambda was “in Fidelity” but not on the build queue

Fidelity is cited often (v0.14, Java solution design, lab research, T-E3 Dynamo/SQS). That did **not** put serverless **HTTP** on the same queue as Dynamo/SQS. Root causes (not “forgot Fidelity existed”):

1. **Concern binning:** v0.14 lists Lambda under **Cloud/deployment** (with EC2/Fargate/CFN/k8s), while **new scope additions §2** only productized Dynamo, SQS/SNS, OpenAPI, OAuth2, multi-DB — not “Lambda is another HTTP entry mechanism.”
2. **Lab proxy substitution:** `fidelity-and-fintech-stack-research.md` maps “AWS Lambda, EKS, …” → **k8s-style deploy manifests**, explicitly “no full AWS account” — EKS stood in for cloud; **Lambda never got a lab package or claim cell**.
3. **Mechanism fit bias:** proven HTTP work is decorator/native-route shaped (Spring/JAX-RS/Flask/Nest). Serverless paths live in **infra**, so they fell into G-L1-07 “IaC later” (low priority) instead of **U-http**.
4. **Partial close looked complete:** **B-dynamo-sqs** / T-E3 closed the Fidelity *data + queue* half of AWS and the row was marked done — easy to read as “cloud Fidelity done” without an HTTP residual.
5. **Evidence portfolio:** until CoE hard-test #2 (aws-saas-boost), every wild/lab API was annotation-framework HTTP. Discovery cadence re-ranked ontology/SQS, not “missing compute entry shape.”

**Correction:** treat serverless HTTP as a **first-class Fidelity concern** (P1 **B-lambda-http** / **B-dynamo-handler-kind**), not a deploy nicety.
