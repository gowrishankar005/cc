### B.4 T-X1-1 — Regression baseline-bump process

`test/regression.test.js` asserts exact values (route sets, node-types, control evidence lines, node/interface counts), not smoke tests. When a catalogue/detector change intentionally shifts a count:

1. Run the affected fixture locally and read the new real value — never guess or round it.
2. Update the assertion to the new real value **in the same commit** as the catalogue/detector change, with a one-line comment naming which task changed it.
3. Do not widen an exact assertion into a range/`>=` check just to make a change pass — that erodes the suite's actual value (catching *silent* regressions).
4. A change that breaks an *unrelated* fixture's assertion is a real regression, not a baseline to bump — investigate before touching the test.
