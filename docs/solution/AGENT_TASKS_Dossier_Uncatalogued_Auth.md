# AGENT TASK — Tune the Evidence Dossier's prompt for `S2-http-without-security-control` (uncatalogued auth judgment)

**Lane:** Independent · **After** nothing (no dependency on the other 5 items in this planning batch — see `docs/solution/BACKLOG.md`'s LLM-assist-candidate rows for the full batch and priority order)
**Governance/DoD:** `CLAUDE.md`'s "Bug fixes are capability work" section does not apply here (this is not a bug fix); `docs/solution/BACKLOG.md`'s "Call-site security-control dossier for uncatalogued auth patterns" row (this file executes that row)
**Why this file exists:** `scope-limitations.yml`'s `call-site-controls-partial` already discloses the gap: only 4 named auth vocabularies are catalogued (`control-requirement-catalogue.yml`), so an HTTP unit using a real but uncatalogued auth pattern reads as "no security-control evidence" and already fires the existing `S2-http-without-security-control` Tier A residual. **No new mechanism is needed** — the residual, the Tier A review path, and `--with-dossier`'s LLM-assist (`tools/review-session/dossier.py`) are all already built and live. The gap is narrower than it looks: nobody has pointed the dossier at this *specific* judgment question ("does this code actually have auth, just not one we catalogue?") with a prompt tuned to ask it. This is the lowest-effort item in the current LLM-assist candidate batch — treat that as a reason to keep the change small, not a license to add scope.

## What you're building

A trigger-aware refinement to `dossier.py`'s existing prompt-building, NOT a new pass, new CLI flag, or new schema field.

Today, `DOSSIER_SYSTEM_PROMPT` (`dossier.py:40-84`) is fully generic across every tier/trigger — it asks the model to "summarize what the evidence actually shows," with no steer toward the specific question an `S2-http-without-security-control` residual actually raises. Since the dossier already receives the residual's own `trigger` field as part of its evidence-assembly input (`build_dossier_prompt` → `llm_common.build_evidence_prompt`, which reads straight from the `residual` dict), the fix is to have `dossier_for_residual` select a trigger-specific *addendum* to the system prompt when `residual["trigger"] == "S2-http-without-security-control"` — asking the model to specifically judge, from the code actually shown to it, whether a real (just uncatalogued) auth/authorization pattern is present, and if so, to name what it looks like (e.g. "a custom header-based token check," "a framework-native guard not in this pipeline's 4 catalogued vocabularies") as one of its `hypotheses`.

## Non-negotiable constraints

- **Every existing hard rule in `DOSSIER_SYSTEM_PROMPT` still applies unchanged** — no new evidence ref, no fact-writing, no confidence beyond what evidence supports, the exact same fixed JSON output shape (`explanation`/`hypotheses`/`evidenceRefsUsed`). The addendum narrows *what to look for*, not *what the model is allowed to claim or output*.
- **Trigger-specific steering, not a second prompt-building code path.** Don't fork `dossier_for_residual`/`build_dossier_prompt` into parallel trigger-specific functions — that's exactly the "narrower-but-instance-specific" anti-pattern `CLAUDE.md` warns against for a single trigger class. Implement as one small, named constant (e.g. `S2_AUTH_JUDGMENT_ADDENDUM`) concatenated onto the base system prompt when the trigger matches, keeping `dossier_for_residual`'s control flow the same for every other trigger.
- **This must generalize past `S2-http-without-security-control` mechanically, not by accident.** If you find yourself hardcoding anything else about this one trigger (a unit id, a file path, a catalogued vocabulary name) beyond the trigger string itself, stop — that's scope creep into a mechanism gap, not this task's prompt-tuning scope.
- **No change to `residuals-schema.json` or the `dossier` field's shape.** The `hypotheses` list is already free-text; this task only changes what's asked, not what's stored.
- **Still opt-in, still `claude`-CLI-only, no `ANTHROPIC_API_KEY` fallback** — unchanged from the rest of `dossier.py`'s existing posture. Don't touch `llm_common.py`'s network-boundary code.

## Where to make the change

`tools/review-session/dossier.py`:
- Add the addendum constant near `DOSSIER_SYSTEM_PROMPT`.
- In `dossier_for_residual` (`dossier.py:160-165`), build the effective system prompt as `DOSSIER_SYSTEM_PROMPT + ("\n\n" + S2_AUTH_JUDGMENT_ADDENDUM if residual.get("trigger") == "S2-http-without-security-control" else "")` before calling `_call_llm`.
- Addendum content should ask the model, using only the evidence already in its prompt (no new evidence source): does this unit's actual code show a real authorization/authentication check this pipeline's 4 catalogued vocabularies wouldn't recognize — and if so, describe the pattern as a hypothesis, citing the exact evidence ref it's grounded in. If the evidence genuinely shows nothing auth-shaped, say so plainly rather than speculating (mirrors hard rule 2, restated for this specific judgment).
