# AGENT TASK — Fix real, live-reproduced bare-name-collision false relationships (cross-service)

**Lane:** Independent · **After** nothing (self-contained bug fix, no dependency on the LLM-assist work below)
**Governance/DoD:** `CLAUDE.md`'s "Bug fixes are capability work" section (this fix must close a mechanism class, not patch one instance), `docs/solution/BACKLOG.md`'s "Possible bare-identifier collision inside multi-hop bridge detection" row (this task closes ONE sub-case of that row, not the whole thing — see "What this does NOT touch" below)
**Why this file exists:** reviewing a real generated `architecture.calm.json` from a live scan of a reference Java microservices banking sample found that **all 10 real, non-placeholder cross-package relationships in the file are fabricated**. Verified directly against real source, not assumed.

## What you're building

Two coordinated fixes to the same root cause, plus real-repo verification — not a new mechanism.

**Real evidence (verified against actual source, not assumed):** `LedgerWriterController.java --calls--> balancereader/Transaction.java` has zero real basis — `LedgerWriterController.java` imports nothing from `balancereader`. The real cause: `balancereader/TransactionRepository.java extends CrudRepository<Transaction, Long>` is a genuine, legitimate same-package reference (Java needs no `import` for a class in the same package) to `balancereader`'s own `Transaction` class — but CodeGraph's cross-package symbol resolution matches the bare name `Transaction` against **any** same-named class across the whole scanned tree, including two other independent services' own, unrelated `Transaction` classes. Each of three genuinely-independent, independently-deployed microservices defines its own domain model reusing common names (`Transaction`, `TransactionRepository`) — a realistic, common shape for a microservice repo that this project's prior evidence base (module-based monorepos, not independently-named-but-identical-shaped services) hadn't exercised before.

**Root cause, precisely located:** `pipeline/src/analysis/cross_package/graphify-reconciler.ts`'s `isBareNameCollision()` (~lines 113-143) is the existing guardrail built for exactly this class of bug (shipped as `B-stereotype-name-collision`, `pipeline/test/regression.test.js` ~line 4079) — but its own docstring names its own coverage gap: it only rejects an edge when the source file has an **explicit, disagreeing import**. When there's no import at all (the same-package-reference case), it degrades to "can't disprove this edge, leave it," per original design. That's exactly the real case here. The fix: `getJavaPackageDeclaration()` (already imported, already used for the destination side) just needs to also be read for the **source** file — when no import exists, a bare reference can only correctly resolve within the source's own package (ignoring `java.lang`, which is never a real `TypedUnit` here, so it can't cause a false rejection). Checked for the one real risk (a non-static wildcard type import silently bringing in a cross-package name with no explicit named import): zero real instances in either of this project's two real Java evidence repos — a real, disclosed, narrow residual, not a blocker.

**A second, independent call site hits the same root cause.** `isBareNameCollision` is currently only called inside `graphify-reconciler.ts`'s own edge loop — not reused by `multi-hop-bridge-detector.ts`, where the file's other 2 false edges (`x-aac-mechanism: "r2c"`) come from. Traced precisely: r2c's second-hop resolution (`multi-hop-bridge-detector.ts` ~line 222, `delegateTargets = importsBySource.get(bridgeNodeId)`) walks the exact same raw `imports`/`references` edges, via a separate `importsBySource: Map<string, string[]>` built at ~line 149 that only retains target node ids, not the real edge objects `isBareNameCollision` needs. Per this repo's own "bug fixes are capability work" (mechanism class, not instance patch) — both call sites need the fix, not just one.

## Non-negotiable constraints

- **Fix the mechanism, not the instance.** Both call sites (`graphify-reconciler.ts`'s direct edge loop, `multi-hop-bridge-detector.ts`'s r2c second hop) must be fixed. Fixing only the one that produced the most visible symptom is exactly the "instance patch dressed as mechanism fix" `CLAUDE.md` warns against.
- **Do not touch `implementersByTarget`** (the FIRST-hop `implements`-edge walk in `multi-hop-bridge-detector.ts`). It's a structurally different, already-carefully-designed disambiguation path (ties into T-LR-3's stereotype-disambiguation) with its own already-documented, still-open, still-unreproduced risk (`BACKLOG.md`'s "Bare-implementer-list collision" row, `scope-limitations.yml`'s `bare-implementer-list-collision-not-reproduced`). This task's real evidence is specifically about `imports`/`references`-kind edges — extending the fix to `implementersByTarget` without a real, reproduced instance there would itself be a speculative fix, which this project's discipline forbids. Leave it alone; the BACKLOG update below must say so explicitly so the amendment doesn't read as if the whole row closed.
- **No regression in the other direction.** The real, legitimate same-package edge (each service's own `TransactionRepository -> Transaction` `connects` edge, within the same package) must still be present after the fix. Suppressing a real edge is exactly the failure mode the original `B-stereotype-name-collision` fix's own precedent test already guards against — verify the same discipline holds here, don't just check that the fabricated edges are gone.

## Where to make the change

**Fix 1** — `pipeline/src/analysis/cross_package/graphify-reconciler.ts`: extend `isBareNameCollision()` — when `findJavaImportForBareName()` returns `undefined`, read the source file's own `getJavaPackageDeclaration()`; if the source's own package differs from the destination unit's package, that's a real, provable collision (reject). Export the function (currently module-private) so `multi-hop-bridge-detector.ts` can reuse it. Update the function's own docstring — it currently asserts the old, now-superseded "no import = can't disprove" limitation as if permanent.

**Fix 2** — `pipeline/src/analysis/cross_package/multi-hop-bridge-detector.ts`: change `importsBySource`'s Map value type from `string[]` (target node ids only) to `CrossPackageEdge[]` (the real edge objects — the exact shape `isBareNameCollision` needs; `CrossPackageEdge` is already importable from `../../scanner/codegraph-crossroot-provider`). At the `delegateTargets`/`uniqueDelegateStores` consumption site, run each candidate edge through the now-exported `isBareNameCollision` before accepting it as a real delegate-store match. Add local `fileLineCache`/`collisionCache` Maps at the top of `detectMultiHopBridgeRelationships`, matching the exact pattern `reconcileCrossPackageEdges` already uses for the same two caches.
